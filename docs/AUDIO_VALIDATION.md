## 当前1.5秒目标的业务预算

给定预算为prefill500ms、输出200token/s、TTS400ms。预算公式是`500 + 5×N_safe + harness/传输 + 400 ≤ 1500ms`：扣掉prefill和TTS后，600ms用于安全朗读资格之前的生成与其他开销。`N_safe`包含到安全边界前的**全部生成token**，包括路由、可能被丢弃的前缀、工具名、完整合法参数及协议结构，不能只算最终短句。当前聊天需完整模型消息确认无工具，因此其安全边界前生成量包含整条消息。

历史Talker usage为null，无法取得实际生成token数；以下明确使用40–60个`N_safe`作为理想预算，不按汉字、音频字数或SSE分包换算。40/200至60/200为200–300ms，因此三条路径的模型与TTS基线为500+200–300+400=1100–1200ms，剩余400–300ms。这里的TTS400ms是假设的首PCM贡献，尚非保证；旧样本实际文本→首包为355–472ms。

| 路径 | 预算N_safe token | prefill + decode + TTS | 剩余至1500ms | 余量须容纳的实际工作 |
|---|---:|---:|---:|---|
| chat | 40–60 | 1100–1200ms | 400–300ms | 完整无工具消息确认、安全朗读与队列/WS传输至浏览器 |
| vehicle | 40–60，含完整工具输出 | 1100–1200ms | 400–300ms | 完整合法参数校验、实际执行回执、具体模板与传输 |
| delegate | 40–60，含完整委托参数 | 1100–1200ms | 400–300ms | 真实登记成功、具体接手确认与传输，不等待Thinker完成 |

这是按业务假设计算的预算，不是三条路径已经达到的实测上界。车控不能用ACK替代实际状态回执，委托不能在登记前说已接手；不允许为了1.5秒先播占位或未核实成功。chat即使先出现完整独立句，同一消息后续仍可能出现tool_calls，不能在尚未确认朗读资格时提前播出。当前实现继续等待整条无工具消息完成后才送TTS，N_safe须计到这个边界；本轮没有实施首句直送或额外路由协议。

prefill500ms是给定业务预算，不能将实际TTFT全部解释成纯prefill：TTFT还包含连接、网络、调度等等待。建连/session可与模型生成重叠，只将暴露在关键路径上的等待计入余量；详细同原点阶段见下方诊断。实际token、HTTP复用或新请求结果必须另有观测，不补造旧usage或缓存命中。

实际委托的goal几乎保留原query，另返回spoken_goal；没有证据说明本轮存在冗长重写，不能据43字符接手句反推解码token。goal、spoken_goal、工具名及JSON结构全部计入N_safe；在给定200token/s假设下，每100个生成token才对应500ms。未来若考虑参数压缩或原query引用，仍须保留完整任务条件并验证安全协议；本轮没有新增这类工具或重构引用协议。

## 测量与分母

通过真实 Chrome 页面表单提交，不由服务端脚本代替浏览器接收音频。启用朗读的用户手势创建并解锁 AudioContext，随后每次 query 生成 client_request_id，以页面 performance.now 记录 submit_perf_ms。独立音频连接的 audio.started 通过 request / turn / playback 三个 ID 关联；合法 PCM 中首次接收到非零 int16 样本时记录 first_nonzero_pcm_perf_ms，两者相减为核心耗时。供应商/模型/服务端时钟不替代浏览器时钟。

界面的“音频测量 / 复制测量 JSON”保留每个已提交请求，包括还未收到 audio.started 的 pending 记录、取消、错误及超标；没有因失败而重试替换样本。后台主动回流没有 query 提交时间，独立保留，不混入 query 分母。刻意打断的功能回归单独留存；若它出现在某次测量导出内，仍作为该文件的失败提交保留，聚合器不会自动剔除。

报告分别列出首个 PCM、首个非零 PCM、向 Worklet 入队、Worklet 首次真实/非零样本渲染通知。入队不是开播，Worklet 主线程观测包含线程通知延迟，不是扬声器声学起点。静音补零、元数据、空包、缓存或占位声音不计有效首音频；本版无音频缓存/替代声音。[Web Audio 规范](https://www.w3.org/TR/webaudio/)。

P50/P95 使用实际有效观测值，报告明确标为 observed-only；当前≤1500ms比例以全部提交为分母，另核对正常完成与语义证据。下方旧表明确保留采样时的≤2秒统计。车控必须具有同轮实际执行成功回执、目标状态，并在声音前观察到回执；委托必须真实登记任务后接手；闲聊不能擅自车控/委托。后台负载样本保存提交时至少两个真实 queued/running 任务的快照。

最终采样为问候、闲聊、温度、左前窗、导航、后台任务接手、后台负载车控各两次，共14次，再追加后台负载闲聊1次，构成15次代表子集。另2次专门验证取消/仲裁，全部纳入17次总分母。只将最终服务重启后的首条 query 标为 first-query-after-restart，其余是同页 warm / 累积历史。连接预热/复用诊断同时保留，不能将首 query 称为已证明的冷模型、冷 TLS 或冷供应商测试。

后续最小修复已使正常流在`[DONE]`后读至HTTP EOF，取消仍可中断；本地真实TCP/HTTP回归用受控Ark响应验证两次请求复用同一TCP连接。这是本地传输验证，尚未重新测量真实Ark或浏览器耗时，不能据此宣称旧超标已消失。新请求启用`stream_options.include_usage=true`，并记录实际`response_headers_ms`、`first_tool_delta_ms`、`service_tier`；headers计时含连接池/连接/HTTP等待，不能当纯推理时间。字段仍须以供应商真实返回为准，旧TTFT、usage与浏览器结果不追填。相关实现与测试见[模型接口](INTERFACES.md)。

当前继续等待完整模型消息与HTTP EOF后提交结果；提前返回并后台drain需要独立取消、尾部错误和恰一次处理隔离，本轮未实现。旧轨迹没有DONE时间点，不能量化DONE→EOF潜在收益；单个句号也不能证明后面没有工具、否定或必要条件，因此没有按首句直接送TTS。

后续优先降低实际模型TTFT，并用真实usage/缓存字段与HTTP传输观测核对瓶颈；当前本地复用回归不能证明真实Ark收益。其次优化达到安全路由边界前的等待和全部生成token量，保持完整参数、回执与登记门控；委托目标已经接近原query，本轮不重构引用协议。Speech会话大多已在模型生成期间建立，继续消除已重叠的握手不是首要收益来源。
