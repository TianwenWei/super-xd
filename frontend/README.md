# 模拟车机验证界面

React + TypeScript + Vite；默认 `http://127.0.0.1:5173`。会话服务需运行在 `127.0.0.1:8000`，Vite 代理 `/api` 和 `/ws`。所有模型与联网密钥仅在后端，前端不读取凭证。

```sh
cd frontend
npm install
npm run dev
```

`npm run build` 运行 TypeScript 检查并生成 `dist/`。

功能：文字流式聊天、自动模拟车端 command ack、十组可展开车况与结构化执行回执、三种预设/结构化自定义人设、后台任务创建/进度/回复/追加/取消、火山朗读、麦克风一键开关连续语音、实际播放状态回报。只有收到 `vehicle.result` 才显示执行成功。窄屏使用“对话/模拟车况/后台任务”标签。长尾工具由服务端按分类加载 skill，首版不实现检索。

车况实际变化后，左栏显示“车况已更新”提示、分组脉冲和金色字段高亮，并用“旧值 → 新值”展示变化，约 6 秒后恢复。变化分组会自动展开，车辆面板会滚动定位；驾驶环境设置也使用同样的变化提示。首次加载、重复快照和未改变车况的操作不会触发动效。减少动态效果偏好下保留静态高亮，关闭脉冲与平滑滚动。

“驾驶环境设置”中的当前位置、国家/地区和车辆时区会进入每轮助手快照，时间由服务端实时更新；清空当前位置后，涉及地点的请求仍需用户提供位置。新会话的初值来自后端 `DEFAULT_LOCATION`、`DEFAULT_LOCATION_COUNTRY`、`DEFAULT_TIMEZONE`，不使用浏览器定位。

每轮生成的车控 function call 在对应助手回复下方以小号等宽字展示函数名和完整参数，多条调用逐条显示；参数校验失败的调用也会保留，展示调用不代表执行成功。刷新/重连通过会话快照恢复。

车控指令使用始终可见的代码块；耗时与轨迹入口继续放在默认折叠的辅助信息中。天气查询按 `lookup.result` 的结构化地点、日期、温度和降水概率显示紧凑卡片，图标读取服务返回的天气代码或 Google 官方图标地址，不分析回答文字。车书 `kind:manual` 结果显示 `hits[].images[]` 的真实原页图片，按 URL 去重；缩略图点击打开原图，原文可按页展开并跳转 PDF。图片加载失败明确提示，不生成替代图片。

全局“模型输出 / Agent 轨迹”入口、每条助手消息与任务卡均可打开轨迹抽屉，按会话/对话轮次/任务筛选。打开时通过 `/api/sessions/{id}/traces?after_id=…` 分页补齐后每秒增量同步；关闭停止请求并保留缓存和游标。记录按 `created_at`、`trace_id` 排序，调用 ID 可定位关联的开始/结束与工具事件。

模型原文与对话区最终反馈分开显示；`content`、`tool_calls`、服务端实际返回的 `reasoning_content` 和 `meta` 可完整展开、复制，缺失字段明确标注，不生成思考过程。取消片段与迟到记录保留状态；未知事件也能展开、复制完整 JSON。窄屏抽屉全屏显示。

朗读固定使用火山 Speech `xiaohe2.0`。页面默认选择语音回复，实际 AudioContext 和音频连接就绪后才在控制 WS 启用语音；浏览器首次阻止自动播放时显示明确的一键进入入口，文字发送的点击/Enter 也会在原始手势内解锁声音，独立 `/ws/{sid}/audio` 传输 mono / 24kHz / s16le PCM；AudioWorklet 增量入队播放，并按浏览器采样率重采样。缺少凭证明确提示，不使用浏览器音色替代。每包携带32字节播放ID，取消、重连和新输入清空旧队列，迟到数据不能重新播放。服务端输入结束后继续消费队列，直到 Worklet 自然 drain 才发送 `playback: false`，用于后台结果播报仲裁。

主验收指标是用户提交到浏览器首个含非零样本 PCM 包的同页 `performance.now` 差值。当前首音频期望目标 ≤1.5秒（1500ms），未达标不阻塞本轮原型交付，标签与着色统一读取 `src/performanceTarget.ts`；只按该主指标着色。首字、车端回执及其他阶段仅作诊断，原始记录保持不变；旧2秒口径是历史要求，未覆盖当前目标。合法首包（可能静音）、首次入队、Worklet 首次真正消费样本的通知、首非零渲染通知分别记录。入队不代表播放；主线程收到渲染通知包含线程传递延迟，不能宣称扬声器声学出声。服务商首包、预连接复用及模型耗时保留为独立诊断。可展开“音频测量”复制完整 JSON，包括会话/页面标识、所有成功/失败/取消、车端实际回执、任务登记和提交时后台任务快照。

模型文字按句送入TTS，provider→浏览器音频也为真实增量流；前瞻预告不能宣称完成，完整工具组校验后才允许下发，实际结果以真实回执为准。新输入立即清空 PCM 队列、取消旧合成，使旧 turn 的迟到文字与音频失效。任务卡进度不自动朗读，后台完成/澄清采用独立流轮次播放。

音频本地验证：`node --test frontend/tests/*.test.mjs`，覆盖44.1k/48k重采样、自然drain、空包/静音、双WS顺序与迟到帧身份隔离。轨迹的audio.text专用展开区显示实际送入Speech的完整文本、来源及原/播字数，可复制；任务全文与来源仍独立保留。

会话ID仅保存于当前标签页 `sessionStorage`。本原型保证连续在线；服务重启丢失会话时会显示失效提示，可点击“新建会话”。这不等于恢复旧会话。

接口约定见项目 `docs/INTERFACES.md`；当前浏览器验收方法见 `UI_VALIDATION.md`；历史截图和完整trace不随源码提交。

页面打开时麦克风关闭，即使浏览器已有权限或旧版保存了开启偏好也不会自动收音。点击输入框旁的麦克风，启动`HandsFreeRecognition`并在同一手势中申请麦克风、解锁声音；实际就绪后按钮高亮，持续监听。VAD 判断说话停顿后自动提交最终识别，一次开启可连续说多轮，回复播放期间继续上传 PCM。再次点击同一个麦克风按钮会退出连续语音并释放麦克风，启动等待期间也可点击取消；未提交片段及迟到 final 都不再发送。等待权限、连接与实际监听分别显示，启动失败可由麦克风或下方入口重试。VAD 新语音只立即停止旧播报，完整 final 提交后才取消旧轮次。部分识别只更新独立预览，不创建消息或执行车控，也不覆盖已有文字草稿。浏览器须允许麦克风，页面需为 localhost 或 HTTPS；ASR、TTS或VAD未就绪时不能启动语音模式，文字和豆包输入法仍可使用。语音回复默认选择开启，独立于麦克风开关；启动失败明确提示，不静默切换模式或音色。

采集使用独立 AudioWorklet，将实际浏览器采样率的单声道音频转换为 16kHz / s16le PCM，每包32ms，通过`/ws/{sid}/listen`持续上传。后端VAD分段，每段只接受当前capture的唯一最终结果。显式停止、断线和卸载释放媒体轨道；权限迟到后也立即停止轨道。编辑/发送文字只丢弃当前未提交的识别片段，保留麦克风和监听 socket；已丢弃的迟到 final 不会提交。控制连接恢复后仅在本页已主动开启且未关闭时重启，首次权限/声音阻止会保留模式选择并提示一键进入，服务授权失败不会自动无限重试。朗读偏好保存在当前标签页；麦克风开启状态不持久化，新建会话或刷新后需要重新点击。有效语音input由服务端清除录音标记。页面只保留持续监听识别链路。

“音频测量”导出保留 `recognition_records`，包括 capture ID、采集/就绪/发送/部分识别/最终识别/提交时间、实际 PCM 字节与包数，以及成功/取消/失败状态；成功提交的 `client_request_id` 可关联原有 PCM 回复记录。ASR 耗时单独记录，不改 query 提交到首非零回复 PCM 的1500ms期望目标。本轮实现仅用隔离媒体/WS测试验证，未操作真实浏览器麦克风。

真实ASR与TTS适配器专项分别使用 `scripts/probe_asr.py`、`scripts/probe_tts_ws.py`，执行会调用外部服务；浏览器导出由 `scripts/audio_benchmark.py` 离线聚合。新批次写入 `data/validation/`，程序WS接收不等于实体麦克风、浏览器渲染或扬声器测量，具体口径见 `docs/AUDIO_VALIDATION.md`。

连续语音前端回归包含真实 App handlers 的连接→自动启动、文字→持续监听、重连恢复、显式停止、provider 授权错误不循环，以及 VAD 停播而保留有效轮次/设备查询。AudioContext 被浏览器暂停时尝试恢复，恢复失败会释放采集并明确提示重新进入，不保留虚假的“持续监听”。麦克风请求浏览器 AEC/降噪/增益；隔离测试不证明实体扬声器回声已消除。
