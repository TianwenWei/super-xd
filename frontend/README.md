# 模拟车机验证界面

React + TypeScript + Vite；默认 `http://127.0.0.1:5173`。会话服务需运行在 `127.0.0.1:8000`，Vite 代理 `/api` 和 `/ws`。所有模型与联网密钥仅在后端，前端不读取凭证。

```sh
cd frontend
npm install
npm run dev
```

`npm run build` 运行 TypeScript 检查并生成 `dist/`。

功能：文字流式聊天、自动模拟车端 command ack、十组可展开车况与结构化执行回执、三种预设/结构化自定义人设、后台任务创建/进度/回复/追加/取消、可选火山朗读与播放状态回报。只有收到 `vehicle.result` 才显示执行成功。窄屏使用“对话/模拟车况/后台任务”标签。长尾工具由服务端按分类加载 skill，首版不实现检索。

每轮生成的车控 function call 在对应助手回复下方以小号等宽字展示函数名和完整参数，多条调用逐条显示；参数校验失败的调用也会保留，展示调用不代表执行成功。刷新/重连通过会话快照恢复。

全局“模型输出 / Agent 轨迹”入口、每条助手消息与任务卡均可打开轨迹抽屉，按会话/对话轮次/任务筛选。打开时通过 `/api/sessions/{id}/traces?after_id=…` 分页补齐后每秒增量同步；关闭停止请求并保留缓存和游标。记录按 `created_at`、`trace_id` 排序，调用 ID 可定位关联的开始/结束与工具事件。

模型原文与对话区最终反馈分开显示；`content`、`tool_calls`、服务端实际返回的 `reasoning_content` 和 `meta` 可完整展开、复制，缺失字段明确标注，不生成思考过程。取消片段与迟到记录保留状态；未知事件也能展开、复制完整 JSON。窄屏抽屉全屏显示。

朗读固定使用火山 Speech `xiaohe2.0`。用户点击勾选后解锁 AudioContext，控制 WS 启用语音，独立 `/ws/{sid}/audio` 传输 mono / 24kHz / s16le PCM；AudioWorklet 增量入队播放，并按浏览器采样率重采样。缺少凭证明确提示，不使用浏览器音色替代。每包携带32字节播放ID，取消、重连和新输入清空旧队列，迟到数据不能重新播放。服务端输入结束后继续消费队列，直到 Worklet 自然 drain 才发送 `playback: false`，用于后台结果播报仲裁。

主验收指标是用户提交到浏览器首个含非零样本 PCM 包的同页 `performance.now` 差值。当前首音频期望目标 ≤1.5秒（1500ms），未达标不阻塞本轮原型交付，标签与着色统一读取 `src/performanceTarget.ts`；只按该主指标着色。首字、车端回执及其他阶段仅作诊断，原始记录保持不变；旧2秒口径是历史要求，未覆盖当前目标。合法首包（可能静音）、首次入队、Worklet 首次真正消费样本的通知、首非零渲染通知分别记录。入队不代表播放；主线程收到渲染通知包含线程传递延迟，不能宣称扬声器声学出声。服务商首包、预连接复用及模型耗时保留为独立诊断。可展开“音频测量”复制完整 JSON，包括会话/页面标识、所有成功/失败/取消、车端实际回执、任务登记和提交时后台任务快照。

当前 provider→浏览器音频为真实增量流；为避免模型先输出文字又调用车控工具造成提前成功反馈，模型文字是否可合成由服务端在工具语义明确后决定。新输入立即清空 PCM 队列、取消旧合成，使旧 turn 的迟到文字与音频失效。任务卡进度不自动朗读，后台完成/澄清采用独立流轮次播放。

音频本地验证：`node --test frontend/tests/*.test.mjs`，覆盖44.1k/48k重采样、自然drain、空包/静音、双WS顺序与迟到帧身份隔离。轨迹的audio.text专用展开区显示实际送入Speech的完整文本、来源及原/播字数，可复制；任务全文与来源仍独立保留。

会话ID仅保存于当前标签页 `sessionStorage`。本原型保证连续在线；服务重启丢失会话时会显示失效提示，可点击“新建会话”。这不等于恢复旧会话。

接口约定见项目 `docs/INTERFACES.md`；实际浏览器验证和限制见 `UI_VALIDATION.md`。

语音输入使用火山 ASR。点击麦克风开始，再次点击结束录音并提交最终识别结果；部分识别仅在独立预览中更新，不创建消息或执行车控，也不覆盖已有文字草稿。浏览器须允许麦克风，页面需为 localhost 或 HTTPS；未配置时按钮禁用，文字和豆包输入法仍可使用。首击在用户手势内解锁现有小何音频，录音期间暂停朗读并阻止后台结果播放；有效最终识别先启用小何，再经原有 query 路径提交一次。TTS 无法启用时明确提示并提交文字，不替换音色。

采集使用独立 AudioWorklet，将实际浏览器采样率的单声道音频转换为 16kHz / s16le PCM，每包默认100ms、上限200ms。`/ws/{sid}/asr` 每次采集独立连接；用户结束后先 flush 剩余真实样本，再发 `asr.stop`，只接受当前 capture 的唯一最终结果。取消、新文字、断线和卸载释放媒体轨道；权限迟到后也立即停止轨道。控制 WS 的 `asr.capture` 独立预留播报位置，取消/错误释放，有效语音 input 由服务端清除，避免将录音伪装为音频播放。

“音频测量”导出保留 `recognition_records`，包括 capture ID、采集/就绪/发送/部分识别/最终识别/提交时间、实际 PCM 字节与包数，以及成功/取消/失败状态；成功提交的 `client_request_id` 可关联原有 PCM 回复记录。ASR 耗时单独记录，不改 query 提交到首非零回复 PCM 的1500ms期望目标。本轮实现仅用隔离媒体/WS测试验证，未操作真实浏览器麦克风。

独立真实语音链路验收脚本位于 `scripts/evaluate_voice_interactions.py`：默认仅打印计划；`python -m scripts.evaluate_voice_interactions --base http://127.0.0.1:8001 --output docs/voice-interactions-run1.json --run` 才执行外部请求。七个语音步骤覆盖六类交互，使用真实小何合成的中文输入fixture，经真实ASR最终文本提交原query，再接收真实回复PCM；固定独立预期校验命令集合、完整状态差异、话题、回执/登记先后和取消身份。fixture缓存可复用，已有输出文件拒绝覆盖。现有run1为Pro对照：7/7语义及传输检查通过，7次程序接收延迟均超过1500ms；Pro不交付，该批不能作为最终Mini验收。完整证据见 `../docs/voice-interactions-run1.json` 和下述验证记录。这是程序WS接收测试，未测实体麦克风、浏览器音频渲染或扬声器声音。

Mini独立首批 `../docs/voice-interactions-mini-run1.json` 使用8003和相同缓存fixture/固定oracle，实际前台与quick任务均为Mini。七条query语义/传输通过，但天气任务达到四步上限失败，因此整批未通过；程序首非零PCM≤1500ms为2/7，仍未全部达标。可用 `--expected-talker doubao-seed-2-0-mini-260428` 在任何provider请求前核对服务配置，防误跑Pro；已有失败记录保留，不作为最终成功交付证据。

后续候选批次 `../docs/voice-interactions-mini-final-20261013.json` 同样失败：按摩仍误选加热、未读取要求的官方天气来源，程序首非零PCM≤1500ms为0/7。其文件名final不表示验收通过。原query自动4/7，独占离线v3修正真实只读查询误判后5/7，按摩与天气失败均保留；并行验收负载及人工来源核查详见 `UI_VALIDATION.md`。
